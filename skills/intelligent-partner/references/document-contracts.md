# 三種文件的最小規格

沿用既有結構；只在新建或重整時選用下列欄位。文件可交叉連結，不複製整份內容。

## 對話紀錄

- 開首：任務、紀錄範圍、日期與「摘要／非逐字稿」標示；連結現行計劃與筆記。
- 每個重要節點：使用者意圖、AI 提案／動作、使用者質疑及理由、修訂或驗收、當時未解項目。
- 只有已知才記時間、輪數與來源；不能從摘要虛構逐字對話或精確時間。
- 新增歷史條目，修正錯引時標明修正；不把後來接受的結論倒寫到早期輪次。

## 學習筆記

- 開首：主題、範圍、更新日期、與紀錄及計劃的分工。
- 按概念組織：問題 → 定義／關係 → 例子／推導 → 驗證及來源 → 邊界 → 未解問題。
- 連結概念的因果、依賴、對照及適用條件，避免只是對話摘錄。
- 應明確分開：作者實務判斷、外部來源支持、模擬例子、已核實結果。
- 一個統計值須有指標、分母、人群、時間、比較與方法；資訊不足留空缺而不編造。

### 思考路徑（有重要轉折時）

在相關知識主題下用 Markdown 小節或表格記錄「起點、觸發、修正、理由、未解」，多個分支可用 Mermaid；工具不是必要條件。紀錄保存先後，筆記保留有助理解的路徑並連回現行概念。不可把後來結論倒寫成一開始已知，也不可從只有結論的舊摘要補造過程。

例：使用者原先想找筆記工具 → 認為建立概念連結困難 → 從 AI 對話想到共同整理 → AI 提出完整筆記不等於理解 → 使用者要求保留思考轉折及認知掙扎。前四者是可見討論；最後要求是新規格，不能宣稱已證明學生效果。

## 計劃

- 頂部：現行階段、完成／待定、停止點、文件分工及下一步。
- 正文：目標／讀者／用途、需求與限制、工作順序／依賴、交付及驗收。
- 把案例及其相關條件放在同一節，讓接手者由上而下可執行。
- 決策狀態可用：已接受、提案待審、待核對、已完成、未通過。無需每句都標籤，但關鍵狀態不可含糊。
- 新決策直接更新相應規格；舊決策的修改理由留在紀錄，不用後文「補充」覆蓋上文。

## 整理例子

- 使用者說「第六章改成學習筆記，不要 Logbook」：更新計劃第六章及相關交付；紀錄保存理由；筆記若涉及概念區分才更新。不要把所有歷史 Logbook 字眼批量刪掉。
- 使用者說「這是有印象的公式，未找到原文」：筆記保留候選解釋及限制；計劃仍標待查，紀錄保存線索。不要寫成已定案例。
- 使用者說「今日先整理，不寫正文」：完成相關檔案整理，接手指令維持停止點。
- 簡短問「某個術語是甚麼」且無持續專案：回答即可，不建立三份空文件。
- 學完論文要做功課：筆記整理概念及證據，計劃安排作業要求與驗收；依需要保留協作紀錄，不代寫不存在的學習證據。


## Markdown 追溯契約

採用既有 ID；新建時可用 L001（對話節點）、C001（主張）、E001（證據）、Q001（未解問題）。ID 一旦引用就保持穩定；不因重排重新編號。只有實際有內容才建立，不強制所有欄位。

### 對話節點模板

```markdown
### L001｜節點題目
- 日期／位置：已知日期或對話定位；摘要，非逐字稿
- 接續：前一節點 ID；分支時標示從哪一節點分出
- 起點問題／當時理解：[使用者] 已表達內容
- 觸發轉折：[使用者質疑／AI 提問／證據 E001] 具體是甚麼
- 可見嘗試與卡點：使用者的理由、比較、失敗嘗試或仍不明白之處
- AI 支援：[AI 建議] 提問、提示、局部示範或完整解說及其理由
- 修正：原判斷 → 修正後判斷；由誰提出、依據及接受狀態
- 分支：保留／暫停／放棄的解釋及原因；沒有表達就標示未確認
- 未解：Q001；需要甚麼證據或下一步才能判斷
```

以上是欄位契約，不是填滿任務。小節或段落亦可，只要資訊可追溯。轉折間的因果僅在對話有依據時記錄；AI 推測的連結標示「AI 重建，待使用者確認」。舊摘要只有結論時寫「過程缺失」，不可補造思考歷程。

### 主張與證據

| 欄位 | 規則 |
|---|---|
| 歸屬 | 使用者判斷／作者主張／AI 建議／外部證據，不能混成「我們認為」 |
| 決策狀態 | 使用者明確接受／暫定／遭反駁／已撤回／未確認；沉默不能升格 |
| 證據狀態 | 已查原文／待核原文／有衝突／僅模擬；已查原文不代表主張已成立 |
| 來源 | 書目或 URL，加頁碼、表格、段落或章節；頁碼不明就明說 |
| 證據作用 | 支持或反駁哪個 C-ID、支持到哪個程度、不能推出甚麼 |
| 修正 | 留舊版本、修正理由、受影響結論與 L-ID；不覆蓋成從未出錯 |

### 學習筆記模板

```markdown
## 概念／主張 C001
- 現行理解與適用邊界：
- 使用者判斷及接受狀態：
- AI 建議／替代解釋及狀態：
- 證據：E001，來源位置、支持／反證與限制
- 思考路徑：L001 → L003；轉折的具體理由
- 已放棄／暫停解釋：原因與可重新考慮條件
- 未解問題：Q001
```

未解問題列出「問題、目前卡點、需要的證據／動作、解決判準、狀態」。沒有到期日或負責人就不編造。只有查證、使用者明確判斷或可重跑驗證通過才能關閉；不因寫了摘要就關閉。

## 增量保存與接續檢查

- logging 追加重大節點；更正另加更正條目並指向舊 ID。
- notes 更新概念的現行理解，同時保留重要版本與路徑連結；plan 只更新工作要求及待辦。
- 收工入口列出現行理解、尚有爭議、待核證據、下一個值得思考的問題和相關 ID。不要自動把未解問題寫成任務已完成。
- 保存前檢查：歸屬清楚、引用可定位、修正有原因、未解未丟失、無虛構對話、內部連結有效、未把點頭當理解、未把 AI 提案當接受。
